# Heuristic Search

#### Best First Search
- Use an evaluation function $f(n)$ for each node
	- Estimate of desirability
	- Expand most desirable unexpanded node
- Implementation:
	- Order the nodes in fringe in decreasing order of desirability
- Special cases:
	- Greedy best-first search
	- A*

#### Greedy best-first search​
- Evaluation function $f(n) = h(n)$ (heuristic)
- = estimate of cost from n to goal
- e.g., $h_{SLD}(n)$ = straight-line distance from $n$ to target
- Greedy best-first search expands the node that appears to be closest to the goal
- Not complete, gets stuck in loops if heuristics are bad
- TC = $O(b^m)$ but a good heuristic can give dramatic improvement
- SC = $O(b^m)$ 
- Not optimal

#### A* Search
- Avoid expanding paths that are already expensive
- Eval function = $f(n) = g(n) + h(n)$ 
- $g(n)$ = cost so far to reach $n$ 
- $h(n)$ estimated cost from $n$ to goal
- $f(n)$ estimated total cost of path through $n$ to goal

#### Admissible Heuristics 
- A heuristic is admissible if for every node $n, h(n), \leq h^*(n)$, where $h^*(n)$ is the true cost to reach the goal state from $n$ 
- An admissible heuristic never overestimates the cost to reach the goal, i.e. it is optimistic.
- Example: $h_{SLD}(n)$ (never overestimates the actual road distance)​
- Theorem: If $h(n)$ is admissible, $A^*$ using TREE-SEARCH is optimal

- This doesn't hold for GRAPH-SEARCH
- A* might discard an optimal path to a repeated state if it is not the first one generated
- If the cost for any action was a constant, this wouldn't be a problem
- OR, if we can guarantee that the first path found to a repeated node was the best path to that node
- We can guarantee this if we impose an extra requirement on the heuristic

#### Consistent Heuristic 
- A heuristic is consistent (or monotonic) if for every node $n$, every successor $n'$ of $n$ generated by any action $a$
	- $h(n) \leq c(n, a, n') + h(n')$

#### Optimality Follows 
- Given $f(n)$ is non-decreasing along my path
- The sequence of nodes expanding by A* is in non-decreasing order of $f(n)$ 
- Hence the first goal to be selected for expansion must be an optimal solution (since all the latter nodes are at least as expensive)

#### Optimality of A*#
- A* expands nodes in order of increasing $f$ value
- Gradually adds "f=contours" of nodes
- Contour i has all nodes with $f=f_i$ where $f < f_{i+1}$ 
	![[Pasted image 20251203131548.png]]

#### Characteristics of A*
- If C* is the cost of the optimal path 
- A* expands all nodes s.t. $f(n) <$ C*
- A* will possible expand nodes on the right of the "goal contour" $(f(n)=$ C*, before finding the goal node 
- A* never expands nodes with $f(n)>$C*

- Does efficient pruning
	- Bits of the tree for which $f(n) > f(G)$ are not expanded 
- Is optimally efficient
	- No other algorithm is guaranteed to expand few nodes than A* (unless there are many tie-breaking nodes) 

#### Properties of A*
- Complete unless there are infinitely many nodes with $f < f(G)$ 
- Exponential TC (in length of optimal solution)
- SC = keeps all expanded nodes in memory
- Optimal

#### More Heuristics
- Often impractical to find optimal solution
	- Variants of A* that find sub-optimal solutions quickly 
	- "More accurate" heuristics that are not strictly admissible

#### Relaxed Problems
- A problem with fewer restrictions on the actions is called a relaxed problem
- The cost of an optimal solution to a relaxed problem is an admissible heuristic for the original problem
