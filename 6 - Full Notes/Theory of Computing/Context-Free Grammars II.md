- Every language is also context-free

	- Add rule $R_i \rightarrow \epsilon$ for each accept state $q_i$

#### Ambiguity
- Consider G with rules:
	- ⟨EXPR⟩ → ⟨EXPR⟩ + ⟨EXPR⟩ | ⟨EXPR⟩ × ⟨EXPR⟩ | (⟨EXPR⟩) | a
- Two derivations of $a + a \times a$
	![[Pasted image 20251026200335.png]]
- Have different parse trees:
	![[Pasted image 20251026200529.png]]
- The grammar generates the string $a+a \times a$ ambiguously

- Ambiguity has to do with the structure of the derivation, not the order of variables substitutions.
- In this example, left-derivations have different parse trees
- A string is derived ambiguously in a CFG $G$ if it has two or more different leftmost derivations
- A grammar $G$ is ambiguous if it generates some string ambiguously
- Sometimes when we have an ambiguous grammar for a language, we can find an unambiguous one

- We have established:
	- ⟨EXPR⟩ → ⟨EXPR⟩ + ⟨EXPR⟩ | ⟨EXPR⟩ × ⟨EXPR⟩ | (⟨EXPR⟩) | a is ambiguous 
- The grammar:
	- ⟨EXPR⟩ → ⟨EXPR⟩ + ⟨TERM⟩ | ⟨TERM⟩
	- ⟨TERM⟩ → ⟨TERM⟩ × ⟨FACTOR⟩ | ⟨FACTOR⟩
	- ⟨FACTOR⟩ → (⟨EXPR⟩) | a 
	- is unambiguous and generates the same CFL as the above grammar
- There exist CFLs that are inherently ambiguous, i.e. they can only be generated by ambiguous grammars
- An example of an inherently ambiguous CFL is the following:
	- $\{a^ib^jc^k | i=j$ or $j=k\}$ 

#### CFGs and Parsers
- CFGs play a big role in compiler workflow: they can be used to specify syntax of a programming language
- A compiler uses a parser to verify the input is grammatically correct
- These parsers are constructed from CFGs
- LR parsers (left-to-right, rightmost derivations) read the input left to right and try to construct the derivation tree from the bottom up reconstructing rightmost derivations
- LL parsers (left-to-right, leftmost derivations) read the input left to right and try to find the leftmost derivation from the top down
