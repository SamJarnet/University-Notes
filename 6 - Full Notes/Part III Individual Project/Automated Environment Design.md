# Automated Environment Design

#### PAIRED:
- Two prior approaches
	- Adversarially generating environments to minimise the reward of the current policy (minimax training)
		-  can generate impossible environments or uninteresting environments
	- Domain randomisation - generatews fully specified environments uniformly randomly regardless of current policy.
		- can generate uninteresting environments
- Solution:
	- Generate environments with maximum regret (difference between the protagonist and antagonist agent return)
		- produces difficult but solvable tasks
	- Introduce an antagonist which is allied with the adversary generating the unsolvable environments.
	- The primary agent we are trying to train is called the protagonist
	- The environmental adversary's goal is to design environemnts so that the antagonist gets a high reward and the protagonist a low one.
		- If the adversary generates an unsolvable environment the antagonist and protagonst would perform the same and the adversary would score zero.
		- If the adversary finds environemtns the antagonist solves and protagonist does not solve, the adversary gets a postive score
	- Insentivised to make more challenging but feasible environments
	- It is recursive and leads to automatic curriculum generation


#### EnvGen:
- Generating and adapting environments via LLMs 
	![[Pasted image 20261028112214.png]]
- Generate multiple environments with an LLM to let the agent learnt different skills effectively, with the Ncycle training cycles, each with 4 steps:
	- Step 1. Promt LLM with 4 components (task description, environment details, output template and feedback from previous cycle). Ask the LLM to fill the template and output various environment configurations that can be used to train agents on different skills
	- Step 2. Train the RL agent in multiple LLM-generated environments, so it can learn different useful skills in parallel
	- Step 3. We first train the RL agent in the original environment to mitigate overfitting to the LLM environments. Then we measure the current RL agent's performance in different tasks in the original environment to check which skills/tasks the agent is still weak at.
	- Step 4. Provide LLM with agent performance from original environment as feedback for adapting the LLM environments in the next cycle to focus on the weaker performing skills
- Basically this idea will be using LLMs to create a JSON that represents the environment instead of directly generating code that changes the environment. this seems a lot easier to implement and would be a good use of a stretch goal.

#### Eurekaverse 
- Suggests unsupervised design methods can work with scalar parameters in low dimensional simulation domains. However, they may not scale up to harder tasks.
- Uses LLM for complete code generation.
- Instructs an LLM to generate novel environments to teach the target task, trains policies for each environment and evalutates the best performing policies to inform the LLM for its next round of environments.
- Method:
	- 1. Uses LLM to generate initial set of environments to train on
	- 2. Uses a process called agent-environment co-evolution, iteratively uses RL to train agents on current set of environments.
	- 3.  Update set of environments so they continue to challenge the best current policy without being too difficult for learning
- As the best polic learns to act more effectively the environments are evolved so they can more effectively improve this policy. 
- This strategy resembles a traditional curriculum learning pipeline but the curriculum is generated by the LLM
